# Lab 10 — Private user-preferences API

## Objective

Build protected API routes that let an authenticated user read and update only their own preferences:

```text
GET   /me/preferences
PATCH /me/preferences
```

## Product story

Nysa selects a time zone and reduced-motion preference during onboarding. Her phone sends only the changed values to beforeburn. The API identifies Nysa from her verified token—not from a `user_id` sent by the phone—and updates only Nysa’s row.

## Security rule

Never design this route:

```text
PATCH /users/{user_id}/preferences
```

unless you are deliberately building an administrator feature with separate authorization rules. An attacker could replace `{user_id}` with someone else’s ID.

Instead:

```text
verified token → current user ID → query/update that user’s preference row
```

## Concepts

| Concept | Meaning |
| --- | --- |
| Request schema | Rules for JSON a client may send. |
| Response schema | The exact safe JSON an API returns. |
| Pydantic | FastAPI’s validation library for schemas. |
| `PATCH` | Update only supplied fields. |
| `exclude_unset=True` | Distinguish a missing field from one explicitly sent by the client. |
| Service function | Reusable business/database logic kept outside route functions. |
| Ownership | A user may access only records belonging to their verified identity. |

## Steps

### 1. Create Pydantic schemas

Create folders:

```bash
mkdir -p app/schemas app/services
touch app/schemas/__init__.py app/services/__init__.py
```

Create `app/schemas/preferences.py`:

```python
from datetime import datetime, time
from uuid import UUID

from pydantic import BaseModel, ConfigDict, Field, model_validator


class PreferencesResponse(BaseModel):
    """Safe preference data returned by the API."""

    model_config = ConfigDict(from_attributes=True)

    user_id: UUID
    time_zone: str
    sleep_start: time | None
    sleep_end: time | None
    reduced_motion: bool
    created_at: datetime
    updated_at: datetime


class PreferencesUpdate(BaseModel):
    """Optional changes to one user's preferences."""

    time_zone: str | None = Field(default=None, min_length=1, max_length=64)
    sleep_start: time | None = None
    sleep_end: time | None = None
    reduced_motion: bool | None = None

    @model_validator(mode="after")
    def time_zone_cannot_be_cleared(self) -> "PreferencesUpdate":
        if "time_zone" in self.model_fields_set and self.time_zone is None:
            raise ValueError("time_zone cannot be null")

        return self
```

### Schema walkthrough

| Code | Meaning |
| --- | --- |
| `PreferencesResponse` | Defines the JSON shape callers receive. |
| `from_attributes=True` | Allows Pydantic to read values directly from a SQLAlchemy model object. |
| `PreferencesUpdate` | Defines the JSON a caller may change. Every field is optional because this is `PATCH`. |
| `Field(min_length=1, max_length=64)` | Reject empty/absurdly long time-zone strings before the database sees them. |
| `model_fields_set` | Tells whether the caller actually sent a field. This distinguishes omitted from explicitly sent `null`. |
| validator | Prevents an invalid request before any write occurs. |

### 2. Create preference service functions

Create `app/services/preferences.py`:

```python
from uuid import UUID

from sqlalchemy.orm import Session

from app.models.user_preference import UserPreference
from app.schemas.preferences import PreferencesUpdate


def get_or_create_preferences(
    session: Session,
    user_id: UUID,
) -> UserPreference:
    preferences = session.get(UserPreference, user_id)

    if preferences is None:
        preferences = UserPreference(user_id=user_id)
        session.add(preferences)
        session.commit()
        session.refresh(preferences)

    return preferences


def update_preferences(
    session: Session,
    preferences: UserPreference,
    changes: PreferencesUpdate,
) -> UserPreference:
    for field, value in changes.model_dump(exclude_unset=True).items():
        setattr(preferences, field, value)

    session.commit()
    session.refresh(preferences)
    return preferences
```

### Service walkthrough

`get_or_create_preferences` means onboarding does not need a separate “create preferences” API call. The first read safely creates a row with database defaults if one does not exist.

`session.commit()` makes a change permanent. `session.refresh(...)` reloads values such as timestamps and database defaults generated by PostgreSQL.

`setattr(...)` is safe here because the schema strictly controls the field names; never call `setattr` with unvalidated client-provided field names.

### 3. Add routes to `app/main.py`

Add these imports near the top:

```python
from uuid import UUID

from app.schemas.preferences import PreferencesResponse, PreferencesUpdate
from app.services.preferences import get_or_create_preferences, update_preferences
```

Add these routes below `/me`:

```python
@app.get("/me/preferences", response_model=PreferencesResponse)
def read_preferences(
    current_user: Annotated[dict[str, Any], Depends(current_user_dependency)],
    session: Session = Depends(get_session),
) -> PreferencesResponse:
    user_id = UUID(current_user["id"])
    return get_or_create_preferences(session, user_id)


@app.patch("/me/preferences", response_model=PreferencesResponse)
def patch_preferences(
    changes: PreferencesUpdate,
    current_user: Annotated[dict[str, Any], Depends(current_user_dependency)],
    session: Session = Depends(get_session),
) -> PreferencesResponse:
    user_id = UUID(current_user["id"])
    preferences = get_or_create_preferences(session, user_id)
    return update_preferences(session, preferences, changes)
```

### Route walkthrough

`UUID(current_user["id"])` converts the verified Supabase user ID into the same type used by PostgreSQL.

There is no `user_id` in the URL or request body. The server derives identity from the validated token, which is the core ownership protection.

FastAPI automatically validates the PATCH body against `PreferencesUpdate`. Invalid JSON never reaches the service function.

### 4. Test routes with fakes and mocks

Add these imports to `tests/test_health.py`:

```python
from datetime import datetime, timezone
from types import SimpleNamespace
from uuid import UUID
```

Add these test helpers below `client = TestClient(app)`:

```python
USER_ID = UUID("0f5b624e-06a2-4b6b-9e25-520b3f6bc3a4")


def sample_preferences() -> SimpleNamespace:
    now = datetime(2026, 10, 4, tzinfo=timezone.utc)
    return SimpleNamespace(
        user_id=USER_ID,
        time_zone="Asia/Kolkata",
        sleep_start=None,
        sleep_end=None,
        reduced_motion=False,
        created_at=now,
        updated_at=now,
    )
```

Add these tests:

```python
@patch("app.main.get_or_create_preferences")
def test_preferences_returns_only_current_users_data(mock_get: Mock) -> None:
    mock_get.return_value = sample_preferences()
    app.dependency_overrides[current_user_dependency] = lambda: {"id": str(USER_ID)}
    app.dependency_overrides[get_session] = lambda: FakeSession()

    try:
        response = client.get("/me/preferences")
    finally:
        app.dependency_overrides.clear()

    assert response.status_code == 200
    assert response.json()["user_id"] == str(USER_ID)
    assert response.json()["time_zone"] == "Asia/Kolkata"


@patch("app.main.update_preferences")
@patch("app.main.get_or_create_preferences")
def test_preferences_patch_updates_only_sent_fields(
    mock_get: Mock,
    mock_update: Mock,
) -> None:
    preferences = sample_preferences()
    preferences.reduced_motion = True
    mock_get.return_value = sample_preferences()
    mock_update.return_value = preferences
    app.dependency_overrides[current_user_dependency] = lambda: {"id": str(USER_ID)}
    app.dependency_overrides[get_session] = lambda: FakeSession()

    try:
        response = client.patch(
            "/me/preferences",
            json={"reduced_motion": True},
        )
    finally:
        app.dependency_overrides.clear()

    assert response.status_code == 200
    assert response.json()["reduced_motion"] is True
    submitted_changes = mock_update.call_args.args[2]
    assert submitted_changes.model_dump(exclude_unset=True) == {
        "reduced_motion": True
    }
```

Also add the imports used by these tests:

```python
from app.main import app, current_user_dependency
```

### Testing walkthrough

- The current-user dependency is overridden so tests never need a real token.
- The database session is fake.
- Service functions are mocked, so route tests focus on HTTP, authentication dependency, validation, and response shape.
- Service functions will receive their own direct tests later using a test database.

## What you learned

Routes should be thin: they handle HTTP, dependencies, and response shapes. Services handle database rules. Schemas validate the client’s input. Most importantly, ownership comes from a verified identity—not a client-supplied ID.
